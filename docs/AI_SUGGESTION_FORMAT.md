# AI Mapping Suggestion Exchange Format

Canonical URL for inclusion in copy-paste AI prompts (link this document, do not paraphrase the format).

## Purpose

v1 has no in-app AI API. The user copies a generated prompt into an external chat, then pastes the structured portion of the response back into intEHRgrator to apply mapping suggestions.

## Response envelope

The AI must return **one fenced JSON block** tagged `intehrgrator-suggestions`. No prose inside the fence. Prose outside the fence is ignored on import.

````markdown
Here is my analysis…

```intehrgrator-suggestions
{
  "format": "intehrgrator-suggestions",
  "version": "1",
  "templateId": "vitals_encounter_v1",
  "suggestions": [ … ]
}
```
````

## JSON schema (version 1)

```json
{
  "format": "intehrgrator-suggestions",
  "version": "1",
  "templateId": "string — must match loaded OPT template id",
  "suggestions": [
    {
      "slotId": "string — stable target slot identifier (see below)",
      "expression": "string — fontoxpath XPath/XQuery expression (not dot-path)",
      "note": "string — optional human-readable rationale"
    }
  ]
}
```

### `slotId` convention

Identifies a value slot in the Template Skeleton unambiguously:

```
{archetypeId}/{path_within_archetype}
```

Examples:
- `openEHR-EHR-OBSERVATION.blood_pressure.v2/data/events/at0003/data/items/at0004/value`
- `openEHR-EHR-OBSERVATION.blood_pressure.v2/protocol/items/at0011/value`

The app resolves `slotId` to a Blockly value input. Unknown `slotId` values are reported on import and skipped.

### `expression` rules

- Must be a single expression evaluating to the target `DV_*` type
- Primary form: JS-shaped mapping expressions per [MAPPING_SPECIFICATION.md](MAPPING_SPECIFICATION.md), e.g. `xpathNumber("/patient/vitals[1]/systolic")`, `trim(xpathString("..."))`
- Allowed transforms: string/math/control-flow functions documented in [BLOCKLY_INTEGRATION.md](BLOCKLY_INTEGRATION.md) utility blocks
- Must not introduce RM structure (no new entries, clusters, or optional RM objects)

## Prompt contents (generated by app)

When the user clicks **Copy AI Prompt**, the clipboard receives markdown containing:

1. **Task** — map source data to openEHR Composition per loaded OPT
2. **Template** — `templateId`, filename, and URL or inline OPT summary (structure of unmapped slots)
3. **Source** — filename and URL or inline source schema/instance summary
4. **Scope** — `full` (all unmapped slots) or `slot` (single selected slot with `slotId`)
5. **Format link** — URL to this document (`AI_SUGGESTION_FORMAT.md` on the deployed site or repo)
6. **Slot manifest** — list of `{ slotId, rmType, archetypeNodeId, label }` for slots needing suggestions
7. **Instruction** — respond with exactly one `intehrgrator-suggestions` fenced JSON block per the linked format

### File URLs in prompts

| Context | URL strategy |
|---------|----------------|
| Files opened from disk | Filename + embedded structure excerpt; user attaches full files in external chat if needed |
| Project saved in IndexedDB | Same; prompt notes project id and filenames |
| Future: hosted artifacts | HTTPS URLs to raw template/source if published |

## Import behavior

1. User clicks **Import Suggestions** (or pastes into import dialog)
2. App extracts the `intehrgrator-suggestions` fenced block (or raw JSON if valid)
3. Validates `format`, `version`, `templateId` against loaded workspace
4. For each suggestion: resolves `slotId` → inserts/parses `expression` into the value block
5. Shows summary: applied / skipped / errors
6. User runs **Test Run** to verify

## Example

```intehrgrator-suggestions
{
  "format": "intehrgrator-suggestions",
  "version": "1",
  "templateId": "vitals_encounter_v1",
  "suggestions": [
    {
      "slotId": "openEHR-EHR-OBSERVATION.blood_pressure.v2/data/events/at0003/data/items/at0004/value",
      "expression": "xpathNumber(\"/vitals[1]/systolic\")",
      "note": "Direct map from first vitals array entry"
    },
    {
      "slotId": "openEHR-EHR-OBSERVATION.blood_pressure.v2/data/events/at0003/data/items/at0005/value",
      "expression": "xpathNumber(\"/vitals[1]/diastolic\")"
    }
  ]
}
```
